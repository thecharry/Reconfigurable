# 布局优化审查与计算流程

日期：2026-09-07。范围：当前启用的 `Optim_Algorithm.m`、`strict_layout_minlp.py`，以及调用器和软件的相关接口。本次只分析，不修改优化器、调用器或软件界面。

## 1. 先给结论

不能根据两小时没有解断言“严格对称的12台推力器问题无解”，也不能再把问题简单归结为运行时间不够。

本次发现的核心问题是：

1. 当前要求的是“任一单台故障后，每个正负轴均存在等推力同步开关的偶数瞬时纯组”，比“存在不同占空比的周期平均纯控制”强得多。
2. 本地搜索是贪心选组与局部最小二乘交替，既没有完成解析拓扑枚举，也没有可靠的拓扑跳转机制。
3. 本地搜索减小的配平残差与严格覆盖数并不等价。本轮残差最小候选只覆盖18项，覆盖最多的候选覆盖140项。
4. 本地结果没有被转化为联合求解的初始解或部分拓扑提示，两个阶段基本上是串行尝试。
5. 联合模型直接处理三角函数、安装位置乘积和大量组成员二进制变量，预处理后出现3444个变量；尚未充分利用严格对称模块的代数结构。
6. 覆盖数不是联合搜索进度；本轮恢复来源为空、种子仍为18，显示140的候选与上一轮完全相同。

最有说明力的对照结果是：固定140项候选的几何不变，允许各台采用不同占空比后，156项周期平均控制需求全部满足0.1的能力门槛；但当前要求的瞬时纯组仍只有140项。这里不是“完全没有故障控制能力”，而是两种可重构标准不同。

这个候选还有近重合安装点，不是可直接制造和使用的工程布局。上述对照只用来区分控制分配约束。

## 3. 固定布局对照计算

### 3.1 如何比较

对最高覆盖候选重新构造控制矩阵，枚举全部4095个非空开关集合。分别保留偶数集合或允许任意台数，并在标况及12种单故障下检查12个正负轴。

此外，固定同一几何，针对每个故障和轴向求解线性规划：

\[
\max_{u,\lambda}\ \lambda,
\qquad A(x)u=s\lambda e_k,
\qquad 0\leq u_i\leq1,
\qquad u_f=0,
\qquad \lambda\geq0.
\]

`u_i` 是第i台推力器在周期内的占空比，可以彼此不同；`lambda` 是该方向最大归一化平均能力；`f` 是故障编号；标况不施加 `u_f=0`。

这里不加最小脉宽、时序峰值、同时开机数量或电源限制。因此线性规划是平均控制能力对照，不能替代严格瞬时调用验证或闭环验证。

### 3.2 对照结果

| 同一最高覆盖候选，改变检查条件 | 满足需求数 |
|---|---:|
| 偶数瞬时纯组，能力门槛0.1，容差1e-9 | 140/156 |
| 允许奇数瞬时纯组，其他不变 | 140/156 |
| 偶数瞬时纯组，门槛改为0.01 | 140/156 |
| 偶数瞬时纯组，门槛改为0.001 | 140/156 |
| 偶数瞬时纯组，纯组容差放宽为1e-6 | 140/156 |
| 不同占空比的平均配平，门槛仍为0.1 | 156/156 |

实际检查了容差 `1e-9、1e-8、1e-6` 与门槛 `0.1、0.01、0.001` 的全部九种组合，最高覆盖候选的偶数组和任意台数组均为140项。

平均分配线性规划的156项均正常收敛，最弱方向最大归一化能力约为 `0.149999999948`，最大六维方程残差约为 `3.20e-11`。因此不是仅凭矩阵满秩来推测可控，而是逐故障、逐方向计算了带非负性和占空比上限的能力。

注意：这只证明该固定候选的差别来自瞬时纯开关状态与平均配平的区别，不能证明在全部几何空间内“偶数要求无影响”或“门槛0.1不限制可行性”。判断全空间影响仍需重新搜索或数学证明。

### 3.3 为什么残差最小却不代表覆盖最多

| 本轮保存的候选 | 严格覆盖数 | 配平残差范数 |
|---|---:|---:|
| 覆盖最多的候选 | 140 | 约0.400000 |
| 残差最小的候选 | 18 | 约0.144222 |

140项候选的16个失败方向，最近组的目标能力几乎为零，单项能力缺口约为0.1。仅这些缺口就贡献了 `sqrt(16*0.1^2)=0.4` 的残差。

另一个候选可以把误差分散到很多方向，使总平方和更小，但大量方向仍超过1e-9的严格纯组容差。局部轨迹也发生过覆盖数从140降到18的情况。程序保存了历史最高覆盖候选，不会丢失140，但局部迭代本身并未保护已经满足的方向。

## 4. 当前究竟加了哪些约束

| 条件 | 代码含义 | 本轮是否值得怀疑为额外限制 |
|---|---|---|
| 12台、3个四推力器模块 | 每个模块4个独立几何参数，总计12个 | 限定了严格对称族，不是一般两安装面自由布局 |
| 严格中心对称及对面镜像 | 位置和推力方向都按规定关系生成 | 是用户选择的构型假设，确实缩小空间，但没有无解证明 |
| 两面在x=±2 m | 面间距4 m，非优化变量 | 固定几何条件，应与卫星尺寸核对 |
| 每模块y∈[0,0.6]、z∈[-0.6,0.6] | 每一对只取一个代表点 | 在当前完整角度和对称z范围内，配合正确整体重编号不必损失该对称族；不能把y和方向独立翻转 |
| alpha∈[0,2pi] | 覆盖完整横向方位角 | 没有固定两个方位角或只选两类模板 |
| beta∈[0,pi/2] | +X面推力的X分量只能非正，-X面只能非负 | 这是单面法向符号限制；若允许反向法向推力，当前范围并未覆盖，需要明确物理许可 |
| 偶数集合 | 只允许2、4、6、8、10、12台；单故障最多10台 | 是当前硬要求；不是只允许两台，也没有只允许同模块组合 |
| 同步瞬时纯组 | 成员按相同额定推力同时打开时，其他五轴总量为零 | 远强于不同占空比的平均配平；是当前核心困难 |
| 任一单故障后十二方向全部满足 | 每个故障方向都要有健康组 | 是目标需求，不是可以默默删掉的冗余限制 |
| 能力门槛0.1 | 每个组的目标方向归一化能力至少0.1 | 正能力门槛必要，但0.1本身应最终由任务需求确定 |
| 最小安装间距与夹角均为0 | 本轮没有施加这两类排斥约束 | 不是它们卡住搜索；反而允许近重合退化布局 |
| 模块y排序 | 联合模型要求y1≤y2≤y3 | 三模块边界相同时，只消除等价模块排列，不要求同高或相同位置 |

不存在的限制：不要求三个模块同一z，不锁定原布局，不禁止对角线和跨模块组合，不在故障后永久禁用原配对中的健康推力器，也没有“只搜索51类”或“只搜索两类解析构型”的活动代码。

`pairs` 在Python模型中只是“入选台数的一半”，不是事先固定的实体配对关系。四台整体纯组不一定能再拆成两个各自纯净的二台组。

## 5. 详细计算步骤

### 步骤1：读取设置与建立几何变量

活动入口在 `Optim_Algorithm.m:488`。前面的旧遗传算法代码位于块注释中，不参与执行。

每个模块m用以下四个量表示：

\[
x_m=(y_m,z_m,\alpha_m,\beta_m),\qquad
x=(x_1,x_2,x_3)\in\mathbb R^{12}.
\]

`y_m、z_m`：该模块在+X安装面上第一台推力器的位置坐标，单位m。`alpha_m`：YZ平面中的方向方位角，单位rad。`beta_m`：方向偏离-X法向的夹角，单位rad。`a=x_face=2 m`：安装面距原点的X向距离，不是软件中名称相似的“位置参数a”。

### 步骤2：由每个模块生成四台推力器

令 `c_m=cos(beta_m)`，`p_m=sin(beta_m)cos(alpha_m)`，`q_m=sin(beta_m)sin(alpha_m)`。

\[
R_m=\begin{bmatrix}a&a&-a&-a\\y_m&-y_m&y_m&-y_m\\z_m&-z_m&z_m&-z_m\end{bmatrix},
\qquad
D_m=\begin{bmatrix}-c_m&-c_m&c_m&c_m\\p_m&-p_m&p_m&-p_m\\q_m&-q_m&q_m&-q_m\end{bmatrix}.
\]

`R_m`的每列是安装位置，`D_m`的每列是单位推力方向。三个模块依次对应推力器1—4、5—8、9—12。

### 步骤3：构造六维控制矩阵

对第i台：

\[
B_i(x)=\begin{bmatrix}d_i\\r_i\times d_i\end{bmatrix},\qquad
B=[B_1,\ldots,B_{12}],\qquad
A=\operatorname{diag}(1,1,1,1/a,1/a,1/a)B.
\]

`B`为6×12矩阵，前三行是单位推力的力分量，后三行是力臂产生的力矩系数。实际满推力控制矩阵为 `F_max*B`。`A`把力按F_max、力矩按F_max*a归一化。

所以本轮归一化门槛0.1分别对应纯力1 N、纯力矩2 N·m。它是组开启状态的能力，不是一次具体仿真指令的占空比。

### 步骤4：枚举全部偶数开关组

`Optim_Algorithm.m:500`附近生成所有非空偶数集合，共：

\[
\sum_{j=1}^{6}\binom{12}{2j}=2047.
\]

每组用12维二进制向量 `b` 表示，`b_i=1`表示该组包含第i台，`b_i=0`表示不包含。将全部组并列成 `M=masks`，大小为12×2047。

`b`不是任意占空比向量。它先规定某一喷气阶段的开关状态，所有被选中的推力器均按额定推力喷气。

`usable`大小为13×2047：第1行为标况，第f+1行为第f台故障；只要组内包含故障推力器，该组就被排除。单故障后共有1023个非空健康偶数集合。

### 步骤5：计算156项需求的最近组与严格覆盖

一次矩阵乘法得到所有组的六维归一化效果：

\[
W(x)=A(x)M.
\]

需求索引是 `(f,k,s)`：`f=0,...,12`表示标况或故障，`k=1,...,6`依次表示Fx、Fy、Fz、Mx、My、Mz，`s∈{-1,+1}`表示方向。共 `13*6*2=156` 项。

令 `e_k` 为第k项为1、其他项为0的六维单位向量，`P_k=I-e_ke_k^T`用于去掉目标轴分量。一个组严格满足需求，当且仅当它健康、台数为偶数，并满足：

\[
\|P_kA(x)b\|_\infty\leq\varepsilon,\qquad
s e_k^TA(x)b\geq\rho-\varepsilon.
\]

`epsilon=pure_tolerance=1e-9`是纯组检查容差，`rho=min_axis_capacity=0.1`是最低目标能力。严格覆盖数C(x)是156项中存在至少一个合格组的项数。

对于尚不满足的布局，程序还必须选一个组引导连续优化。`Evaluate_Layout`为每组计算：

\[
E_{fks}(x,b)=\|P_kA(x)b\|_2^2+
\left[\max(0,\rho-s e_k^TA(x)b)\right]^2.
\]

它逐项贪心选择 `b* = argmin E`。第一项惩罚其他五轴的干扰，第二项惩罚目标能力不足；目标能力超过门槛后不再奖励更大的能力。

代码还排除“对目标轴在所有几何下都恒为零”的组合。这个排除基于每个模块的行符号系数，不能排除仅在当前几何处退化为近零的组合。

### 步骤6：生成初值

`Search_Seeds`依次使用显式初值、恢复文件候选及其小扰动、若干结构化模板、当前布局提取种子，再补充全范围随机起点。随后只按整个模块重排序并去重。

本轮恢复来源为空，所以不是上轮候选恢复运行。模板只是起点，不是搜索空间的硬限制；但局部求解的结果仍会受起点影响。初值数量64不是遗传算法种群规模。

### 步骤7：交替选组与固定组局部配平

`Search_From`在每个初值上执行：评价当前几何 → 为每项选一个最近组 → 对重复“组编号、目标方向”去重 → 固定这些组 → 调用lsqnonlin调整12个几何变量 → 再重新选组。

固定组集合记为T，内层求解：

\[
\min_{\ell\leq x\leq h}\sum_{(b,k,s)\in T}
\left\{\|P_kA(x)b\|_2^2+
[\max(0,\rho-s e_k^TA(x)b)]^2\right\}+\|r_{install}(x)\|_2^2.
\]

`ell、h`分别是12个变量的下界和上界。`r_install`是安装间距和夹角违反量；本轮两项限制关闭，所以这部分为空。

每段最多8次迭代，每个初值最多120次名义迭代预算，即最多15段；也会因参数和选组不变、内部停止条件或阶段时限提前结束。本地阶段是“最多60秒”，不是“至少运行60秒”。本轮64个初值在8.98秒内全部结束，剩余时间直接交给联合求解。

lsqnonlin寻找局部最小二乘解，不保证找到零残差或全局解。它的残差向量接口和局部解性质见[MathWorks说明](https://www.mathworks.com/help/optim/ug/lsqnonlin.html)。

### 步骤8：没有完整候选时启动联合求解

`Run_Joint_Solver`把变量边界、门槛和剩余时间传给Python后端。当前没有把本地候选显式设置为联合求解的初始解，没有传入本地选组作为部分拓扑提示，也没有恢复上次的搜索树。

Python把每个需求的组成员也设为未知二进制变量 `b_fks,i`，与12个几何变量一起求解。利用严格模块对称性，只显式处理故障1、5、9以及各自12个正负轴，共36项。每个代表对应其模块的4种故障；同一全局编号置换仅改变控制矩阵的行符号，保留所有正负轴就覆盖了这些等价工况。标况由健康备用组的存在性自动满足，最后仍复核完整156项。

每项约束为：

\[
b_i\in\{0,1\},\quad b_f=0,\quad
\sum_{i=1}^{12}b_i=2n,\quad n\in\{1,2,3,4,5\},
\]
\[
P_kA(x)b=0,\qquad s e_k^TA(x)b\geq\rho.
\]

共有432个声明的二进制成员变量，其中36个故障成员固定为0；另有36个整数组台数变量和12个几何变量。展开非线性表达式后，本轮日志显示3444个变量。

目标函数是 `min 0`，即纯可行性问题；不是最小干扰优化，也不是最大化最弱故障能力。找到首个求解器可行候选即停止。SCIP利用松弛、传播、切平面和分支定界处理混合非线性模型，其方法说明见[SCIP官方资料](https://www.scipopt.org/workshop2020/slides/minlp.pdf)。

### 步骤9：独立复核，再验证调用器

只有存在完整候选，才独立重建布局并枚举全部2047组，复核安装边界、标况和12种故障的所有正负轴。对每项选取严格组中能力最大的组，形成布局能力证明。

随后 `Verify_Invocation`针对156项分别调用现有“最简主备分配 + 同步分时复用”，检查实际选择的组是否健康、偶数、瞬时纯净、没有使用冲量裕度降级。这里把最小脉宽暂设为0，只验证结构，不改变真实仿真参数。

需要注意当前接口缺口：它计算了调用器实际选组能力，却没有再用rho检查该能力是否达标。布局中“存在足够强的组”与最简调用器“实际选择足够强的组”之间还缺少这一道检查。本轮没有进入该阶段，因此这不是本次找不到布局的原因。

### 步骤10：返回与保存

全部复核通过才返回新布局并标记feasible；否则保存诊断MAT、TXT、求解器日志，保留软件已有布局不变。

最高覆盖由 `Observe`更新；联合运行中的回调只报告已用时间比例。故障后覆盖140不变与联合节点不断增加可以同时发生。

## 6. 按重要性审查代码问题

### 6.1 搜索方法与原先“拓扑枚举”设想不一致

定位：`Optim_Algorithm.m:640`和`strict_layout_minlp.py:66`。

枚举2047个组只是枚举“某个需求的一个组有哪些成员”，不是枚举“十二个轴的主备组如何共同组成一个完整拓扑”。本地只取当前最小残差的一个组；联合求解用二进制变量隐式表示全部组合，但没有先形成解析拓扑类、进行一致性剪枝、再逐类求几何。

这不意味着活动模型仍只限于两类模板，但也不能声称已经完成全部解析拓扑枚举。是否有全局求解能力与是否已经穷尽搜索是两件事。

### 6.2 局部目标与严格可行性之间缺乏有效引导

定位：`Optim_Algorithm.m:647`、`:670`、`:869`、`:905`。

零残差与可行性方向一致，但非零残差的大小不能代表严格覆盖好坏。本轮140项候选的残差0.4反而大于18项候选的0.1442。对多个需求逐项贪心选出的组合，还可能彼此要求不相容的几何条件。

去重也带来额外差异：`Evaluate_Layout`把13种工况重复需要同一个组的残差重复计数，而固定组内层对相同“组、方向”只计算一次。它们的零点一致，非零时权重不同，所以外层记录的残差不保证随内层最小化下降。这是启发式设计缺口，不是已经证明所有候选无解。

### 6.3 没有充分利用严格对称的物理代数结构

定位：`strict_layout_minlp.py:31`和`:73`。

对单个模块，定义以下归一化系数：

\[
h_m=(y_mq_m-z_mp_m)/a,\quad
g_m=q_m+z_mc_m/a,\quad
k_m=p_m+y_mc_m/a.
\]

其中h是四台共同的Mx系数，g是My系数幅值，k是Mz系数幅值。该模块的控制矩阵可直接写为：

\[
A_m=\begin{bmatrix}
-c_m&-c_m&c_m&c_m\\
p_m&-p_m&p_m&-p_m\\
q_m&-q_m&q_m&-q_m\\
h_m&h_m&h_m&h_m\\
-g_m&g_m&g_m&-g_m\\
k_m&-k_m&-k_m&k_m
\end{bmatrix}.
\]

它还满足 `c_m^2+p_m^2+q_m^2=1` 和 `c_m*h_m=q_m*k_m-p_m*g_m`。

给定一个组在该模块中的4个二进制成员，把它们记为b1到b4，并定义整数系数：

\[
t=b_1+b_2-b_3-b_4,\quad v=b_1-b_2+b_3-b_4,\quad
w=b_1-b_2-b_3+b_4,\quad n=b_1+b_2+b_3+b_4.
\]

该模块对整组的贡献就是 `[-c*t, p*v, q*v, h*n, -g*w, k*w]^T`。整组只需对三个模块求和。这一表达可用于有限整数模式筛选、等价重编号和拓扑线性一致性检查，再叠加少量物理非线性关系。

当前模型没有充分利用这种结构，而是把每个需求的原始几何表达式与二进制变量直接相乘。建议先重写共享物理系数、验证等价性并实测模型规模；不能未经测试就承诺速度提升多少。尤其不能直接除以c来消元，因为允许beta=pi/2时c=0，必须正确保留该边界分支。

### 6.4 两个阶段没有有效衔接，且没有持续搜索机制

定位：`Optim_Algorithm.m:554`和`:1014`。

联合后端没有消费本地的组合信息。本地初值用完就结束，不会自动把剩余本地预算用于新起点或缺项修复。本轮实际只花8.98秒在本地，这说明把总时限从600改成7200，主要只是延长同一种联合搜索，不会自动多探索本地拓扑。

候选恢复只恢复几个几何起点；搜索树不恢复。软件仅在同一实例仍保存上一轮OptimResult时自动设置恢复文件。本轮日志证实这一恢复没有生效，原因可能是重启了软件或状态被清空，不能仅凭记录确定是哪一种。

### 6.5 显示的覆盖数与实际搜索状态脱节

定位：`Optim_Algorithm.m:665`和`:1057`，`source/RCDesignerPrototype.m:2563`。

联合搜索期间只有时间进度，界面继续显示此前本地覆盖数。建议分别显示“本地最佳覆盖”“联合已处理节点”“联合可行解数”“终止原因”，避免让用户把140理解为两小时持续优化的同一个指标。

### 6.6 最简调用和能力门槛尚未完全对齐

定位：`Optim_Algorithm.m:976`、`:1007`，`Thruster_invocation.m:464`。

优化证明挑选最大能力组；调用器优先挑选最小台数组，并不保证选中同一个组。验证函数只记录实际组能力，没有强制实际组能力也不低于门槛。下一版应决定“先满足任务能力门槛，再最小台数”，或至少独立报告并检验实际可调用能力。

本轮无任何完整候选进入此阶段，所以不能把找不到布局归咎于调用器最后筛得太严。

### 6.7 工程可用性约束并不是当前瓶颈

本轮最小间距和夹角均为0。最高覆盖候选三个模块的y都约为2.83e-8 m，中间模块z也接近0，同一面该模块的两台安装点几乎重合。优化器没有要求它们必须这样放，而是局部求解自然走到了边界附近。

因此现阶段不是“安装限制太多”，反而尚未排除不可制造的近重合候选。增加实际间距会进一步缩小空间，应在数学可行性诊断与工程约束诊断中分别记录，不能用退化布局作为最终成功结果。

## 7. 下一版建议的顺序

1. 先统一验收标准：分别记录非负不同占空比的平均可重构性、健康瞬时纯组存在性、偶数限制、能力门槛、真实安装约束，不把它们混为同一个“可重构”。最终硬要求不经用户同意不变。
2. 增加分层可行性诊断：对固定候选做本报告的对照；对整个设计空间，则按层次重新求解或建立必要条件。固定候选试验不能代替全空间结论。
3. 优先改进拓扑层：利用模块整数系数形式，对多个需求的候选组合进行相容性检查和回溯，而不是每项永远只取一个最近组。保留严格故障纯组硬约束。
4. 改进局部连续求解：统一内外层权重，记录每项耦合与能力缺口，对缺失方向实施有记录的修复，保留多个不同拓扑候选。不能只根据一个总残差判断进展。
5. 联合模型共享物理系数并接入本地信息；用有明确范围的基准测试比较原模型和等价改写模型，再决定是否长时间运行。
6. 修正界面状态、恢复机制和实际调用能力门槛复核，最后才进入最弱故障能力最大化。

不建议现在继续直接提高时限，也不建议未经诊断就取消严格对称、偶数台或瞬时纯组要求。当前有充分证据说明搜索实现需要改进，但还没有证据证明这些硬要求在整个几何空间必然互相矛盾。
